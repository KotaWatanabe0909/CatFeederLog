# 要件定義書 — CatFeederLog

## 1. プロジェクト概要

猫の給餌を家族・同居人と共有管理するスマホ向け Web アプリ。  
「誰かがもうやった？」という二重給餌を防ぐことを最重要ユースケースとする。  
オープンソースとして公開し、誰でも自分の猫用にカスタマイズして使えることを想定する。

### コアUX原則

**記録コストの最小化**が最重要。記録が面倒になると継続できなくなるため、給餌記録は可能な限り少ないタップで完了できる設計にする。

- 餌場の横に **QR コードを印刷して貼る**。スマホで読むと即座に記録画面が開く
- 初回のみログイン（Google OAuth 等）、以降はセッション維持（PWA でホーム画面に追加）
- 記録画面では「給餌した」ボタン1タップで完了。フードは前回と同じをデフォルト値にする
- 詳細（食べた量・フード変更）は後から任意で補完できる
- **将来的に NFC タグへ移行可能**。QR と NFC は同じ URL を使うため移行コストはほぼゼロ

## 2. ユーザー

| 属性 | 内容 |
|------|------|
| 利用人数 | 複数人（家族・同居人） |
| 管理対象 | 猫 1 匹（設定で複数対応できる設計にする） |
| デバイス | スマートフォン（iOS / Android） |

## 3. 機能要件

### 3.1 コア機能（MVP）

| # | 機能 | 説明 |
|---|------|------|
| F01 | クイック給餌記録 | QR 読み取り → 記録画面 → 「給餌した」1タップで完了。時刻は自動記録、フードは前回と同じをデフォルト値にする |
| F02 | 詳細補完 | 食べた量（完食/残した）・フード変更は後から任意で編集できる |
| F03 | 当日の給餌状況表示 | ホーム画面で「今日の朝ごはんは済んでいるか」が一目でわかる |
| F04 | プッシュ通知 | 給餌後、共有メンバー全員に通知する（二重給餌防止） |
| F05 | リマインダー | 固定スケジュール（朝・晩等）に給餌忘れをプッシュ通知する |

### 3.2 履歴・分析機能

| # | 機能 | 説明 |
|---|------|------|
| F06 | 給餌ログ一覧 | カレンダー形式または一覧表で過去の記録を確認できる |
| F07 | 食欲トレンドグラフ | 残した量の推移をグラフ表示し、体調変化を把握できる |
| F08 | CSV エクスポート | 全記録をダウンロードして独自分析できる |

### 3.3 設定機能

| # | 機能 | 説明 |
|---|------|------|
| F09 | 猫プロフィール設定 | 名前・品種・生年月日（個人データはコード外で管理） |
| F10 | フードマスタ管理 | よく使うフードを登録しておき、記録時に選択できる |
| F11 | 給餌スケジュール設定 | 朝・昼・晩など給餌タイミングを設定する |
| F12 | メンバー招待 | URL / QR コードで家族を招待し、同一データを共有する |

---

## 4. 非機能要件

| 項目 | 要件 |
|------|------|
| プラットフォーム | スマホブラウザ（PWA 対応を目標） |
| 記録トリガー | QR コード（Phase 1）→ NFC タグ（Phase 2 以降、同一 URL のため移行コストほぼゼロ） |
| 認証 | Google OAuth 等のソーシャルログイン。初回のみ、以降はセッション維持 |
| データ保存 | クラウド DB（Supabase を第一候補） |
| 個人データの分離 | コードとデータを完全分離する。猫名・フード・スケジュール・メンバー構成はすべて DB に入れ、コードには一切書かない。OSS として誰でもデプロイして自分の猫用として使えることを担保する |
| オープンソース | Public リポジトリ。誰でもセルフホストして使えることを目標 |

---

## 5. 画面一覧（概要）

1. **ホーム** — 今日の給餌状況（朝・晩の済み/未済）、直近の記録
2. **記録入力（QR/NFC 起動）** — 「給餌した」1タップで完了。フード・食べた量は任意で補完
3. **ログ** — カレンダー表示 + 一覧表示の切り替え
4. **グラフ** — 食欲トレンド（週・月単位）
5. **設定** — 猫プロフィール / フードマスタ / スケジュール / メンバー管理

---

## 6. 技術スタック（候補）

| レイヤー | 候補 | 備考 |
|---------|------|------|
| フロントエンド | Next.js (App Router) | SSR + PWA 対応しやすい |
| バックエンド | Next.js API Routes / Supabase Edge Functions | サーバー管理コスト最小 |
| DB | Supabase (PostgreSQL) | リアルタイム同期・認証が揃っている |
| 通知 | Web Push API + Supabase | PWA でプッシュ通知 |
| ホスティング | Vercel | Next.js との親和性が高い |

> 技術スタックは設計フェーズで確定させる。

## 7. 優先度・フェーズ分け

| フェーズ | 内容 |
|---------|------|
| Phase 1 (MVP) | F01〜F04、ホーム・記録入力画面、Supabase 連携、複数人共有 |
| Phase 2 | F05〜F07、ログ画面、グラフ画面 |
| Phase 3 | F08〜F12、CSV エクスポート、フードマスタ、PWA 化 |
